# Change log: NativeTabs BottomAccessory inline-mode fix

Goal: make the tab bar minimize on scroll (`minimizeBehavior="onScrollDown"`) so the
`NativeTabs.BottomAccessory` mini player enters inline mode. Investigation showed the
minimize never triggered on ANY tab, because on iOS 26 UIKit drives minimization off
`UIViewController.contentScrollView(for:)`, and its default search cannot find React
Native scroll views through the `NativeTab → nested Stack → screen` hierarchy
(react-native-screens 4.25.2 does not override it; see
https://github.com/callstack/react-native-bottom-tabs/issues/496 for the same bug in
callstack's lib and https://gist.github.com/pugson/0ea6124c2590984793a8a6afbfcaa1f4 for
the equivalent fix there).

## Changes (in order applied)

### 1. `node_modules/react-native-screens/ios/tabs/screen/RNSTabsScreenViewController.mm`
Added a `contentScrollViewForEdge:` override + BFS helper so UIKit can find the
screen's UIScrollView and drive tab bar minimization. Captured as
`patches/react-native-screens+4.25.2.patch` via patch-package.

**Rollback:** delete `patches/react-native-screens+4.25.2.patch`, then
`npm install` (or revert node_modules: `npx patch-package react-native-screens --reverse`),
then rebuild the iOS app (`npm run ios`).

### 2. `patches/react-native-screens+4.25.2.patch` (new file)
Generated by `npx patch-package react-native-screens`. Rollback: delete the file.

NOTE: a native rebuild (`npm run ios`) is required for the patch to take effect, and
again after rolling it back.

## ⚠️  When upgrading react-native-screens

**Before deleting the patch, check whether the fix is now upstream.**

Open the new version of this file:
`node_modules/react-native-screens/ios/tabs/screen/RNSTabsScreenViewController.mm`

Check for **all three** of the following — the upstream fix must have all of them:

1. **`contentScrollViewForEdge:` override** — method must exist and return a
   `UIScrollView` when `edge & NSDirectionalRectEdgeBottom` is non-zero.
2. **`setContentScrollView:forEdge:` in `viewDidLayoutSubviews`** (or equivalent
   eager push-registration) — so React Native scroll views that mount after the
   view controller appears are registered with UIKit.
3. **Re-registration in `viewDidAppear:`** — UIKit silently ignores
   `setContentScrollView:forEdge:` calls made while a tab is off-screen; the
   re-registration on appearance is required for cold-start on the Home tab.

A quick grep to check:
```
grep -n "contentScrollViewForEdge\|setContentScrollView" \
  node_modules/react-native-screens/ios/tabs/screen/RNSTabsScreenViewController.mm
```

If the upstream file already handles all three points, you can safely delete
`patches/react-native-screens+4.25.2.patch` (patch-package will also tell you
the patch fails to apply if the hunks are already present).

If the upstream fix is partial or missing, update the patch for the new version:
1. Apply the missing pieces to the new `RNSTabsScreenViewController.mm`.
2. Run `npx patch-package react-native-screens` — this creates
   `patches/react-native-screens+<new-version>.patch`.
3. Delete the old `patches/react-native-screens+4.25.2.patch`.
4. Rebuild iOS (`npm run ios`).

### 3. CocoaPods upgraded 1.15.2 → 1.16.2 (Homebrew, system-wide)
`pod install` was failing for this project regardless of the accessory fix: CocoaPods
1.15.2 cannot parse the Xcode 16+ `PBXFileSystemSynchronizedRootGroup` used by the
`src/native` folder in `ios/LAABSAudiobookshelf.xcodeproj`. Upgraded with
`brew upgrade cocoapods`.

**Rollback (not recommended):** `brew install cocoapods@<old>` isn't versioned in brew;
you'd have to pin/downgrade manually. Old version cannot build this project anyway.

### 4. `ios/Podfile.lock` regenerated
Pod versions in the lockfile snapshot no longer matched the updated node_modules
(ExpoModulesCore, ExpoFileSystem, etc. — the recent `package.json`/`package-lock.json`
update), so `pod install` was aborting. The lockfile is NOT git-tracked, so the
original was backed up to `ios/Podfile.lock.backup-pre-accessory-fix`.

**Rollback:** `mv ios/Podfile.lock.backup-pre-accessory-fix ios/Podfile.lock` (note:
the old lock won't install until node_modules pods are reverted too).

### 5. `ios/LAABSAudiobookshelf.xcodeproj/project.pbxproj`: `objectVersion = 70` → `60`
CocoaPods' bundled Xcodeproj (1.27.0) cannot parse object version 70 (Xcode 26 format)
— open upstream issue (CocoaPods/CocoaPods#12889). Community-standard workaround is
downgrading to 60; Xcode/xcodebuild parse it fine. Backup saved to
`ios/LAABSAudiobookshelf.xcodeproj/project.pbxproj.backup-pre-accessory-fix`.

**Rollback:** restore the backup file (or just `sed` objectVersion back to 70) — but
pod install will then fail again until CocoaPods/Xcodeproj fix upstream support.
Note: Xcode may rewrite objectVersion back to 70 when it saves the project; if so,
re-apply the sed before the next `pod install`.
