Deep Linking

Shared-book links open straight to a book's detail screen, even from a cold start. All route-path knowledge is kept in one tiny utility so assumptions don't leak across files.

The link format

The app's custom scheme is laabsaudio, and a shared book is just the item id:

laabsaudio:///{libraryItemId}

The public URL deliberately omits (tabs) and (home) even though the internal Expo Router route is /(tabs)/(home)/[libraryItemId] — those are route groups, not URL segments. The link is built with Linking.createURL(`/${libraryItemId}`).

One utility owns book links

src/navigation/book-links.ts is the single place that knows how book URLs work, so the route shape isn't re-spelled across the app:

FunctionPurpose
getBookDetailHref(libraryItemId)Internal Expo Router href for in-app navigation (also preserves Home/Search source + the one-time download-sheet token).
createSharedBookLink(libraryItemId)The public laabsaudio:///… link shared outside the app.
extractBookDetailIdFromUrl(url)Parses an incoming deep link back into a libraryItemId.

Sharing a book

The share action comes from the Link.MenuAction in BookContainer.tsx, with logic in src/sharing/book-share.ts. One detail is intentional and easy to get wrong: 

await Share.share({
  message: `${title} -> Open in LAAB -> ${deepLink}`,
  url: remoteCoverUri, // the cover image, NOT the deep link
});
🔗
Link in message, cover in url

The deep link goes in message; the url field is the remote book cover (derived from libraryItemId, tokened when useTokenWithCoverImages is on). They're separated on purpose so the share sheet previews the cover while still carrying the openable route link.

Cold start needs a guard

Warm-start links just work — Expo Router is already running and navigates immediately. Cold-start links needed one extra guard in src/app/_layout.tsx: the root layout's fallback logic would redirect an authenticated user toward Home before the initial deep link was processed, stealing the navigation. Startup now waits on the resolved initial URL (initialDeepLinkBookId) before applying route redirects, so the link wins.

⏱️
Why it ties into startup

This is the initialDeepLinkBookId !== undefined gate on the startup path — route redirects wait for Linking.getInitialURL to resolve so a cold-start deep link isn't overwritten by the default authenticated route.
