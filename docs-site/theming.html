Theming

A deliberately small token set, applied consistently. Built on Uniwind, with light and dark resolved from the system theme.

🎨
Principle

Use the six canonical tokens everywhere; reserve the accent for genuinely interactive emphasis. Don't hardcode neutral colors.

The canonical tokens

TokenUsed for
--color-bgApp / page background
--color-surfaceCards, sheets, panels
--color-textPrimary text and icon color
--color-text-mutedSecondary / supporting text (metadata only)
--color-borderBorders, dividers, disabled tracks
--color-accentPrimary interactive emphasis — tabs, slider thumb, primary buttons

Tokens live in src/global.css under @layer theme, with light/dark defined via Uniwind variants inside :root (@variant light { … } / @variant dark { … }).

Three ways to read a token

  1. Utility classes (preferred): bg-bg, bg-surface, text-text, text-text-muted, border-border, bg-accent / text-accent / border-accent.
  2. JS style props / third-party props: useThemeColors() from src/theme/use-app-theme.ts — for ActivityIndicator, Slider, SymbolView, inline style.
  3. Navigation theme sync: useNavigationTheme() from the same module, wrapped via ThemeProvider in src/app/_layout.tsx.

Accent rules

Use accent forAvoid accent for
selected tab icon/labellarge text blocks
slider active track + thumbwhole-page backgrounds
primary call-to-action buttonsnon-actionable surfaces
active selection states—

Component checklist

  1. Replace hardcoded neutral colors with tokens.
  2. Keep one dominant surface and one border tone.
  3. Use muted text for metadata only.
  4. Use accent only on actionable / high-emphasis elements.
  5. Verify both light and dark by switching the system theme.
🟥
Semantic exception

Error / warning / success messaging may use dedicated semantic colors — keep those isolated to feedback components, not general layout.
