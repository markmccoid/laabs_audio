Build & Ops

How EAS turns this repo into an installable app — and the one CNG gotcha that can silently drop a native patch from the build that runs on a device.

This is a CNG (managed) build

The native ios/ folder is gitignored. It exists on your machine (from a local expo prebuild / expo run:ios) but never reaches EAS. So EAS regenerates the native project from app.json + config plugins on every build. That single fact governs how anything native — patches, Podfile edits, native config — has to reach a build. 

# which mode am I in?
git check-ignore ios/Podfile && echo "CNG (ios gitignored)" || echo "bare (ios committed)"

The EAS build sequence

The patch-package gotcha

A react-native-screens patch worked perfectly in the local simulator but had no effect on a physical device installed from EAS. The cause: the shipped RNScreens.framework was compiled from unpatched source — the patch never made it into the binary, because postinstall patch-package didn't survive the CNG prebuild sequence.

🩹
Fix: use the EAS hook, not just postinstall

Add the dedicated build-server hook so the patch lands at the right time:

// package.json → scripts
"postinstall": "patch-package",            // local installs
"eas-build-post-install": "patch-package"  // EAS build server

Verify a native patch deterministically

Objective-C selector names survive into the compiled binary as plain strings, so you can prove whether a native patch is present without reading (encrypted) build logs. Pick a unique symbol the patch introduces and grep the shipped framework: 

# download the IPA, unzip, then:
strings -a "RNScreens.framework/RNScreens" \
  | grep -c "rns_findDescendantScrollViewInView"
# 0 = patch MISSING · >0 = patch present

Get the IPA URL from eas build:view <id> --json → artifacts.buildUrl. (EAS build logs are encrypted at rest, so inspecting the IPA is the practical CLI check.)

📌
Takeaways

Gitignored ios/ ⇒ managed build ⇒ EAS regenerates native. "Works in the simulator" ≠ "works in the EAS build" — the simulator uses your local native project; EAS regenerates its own. For anything that must exist at native-compile time, use eas-build-post-install.
