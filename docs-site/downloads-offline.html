Downloads & Offline

Downloading a book makes it playable with no network at all. The two halves of this page — getting files onto the device, and behaving correctly once the network is gone — are what make offline listening feel seamless.

Downloading a book

Exactly one book download is active at a time, owned by device-books-store. The visible progress bar represents the whole book, not the current file — it should travel 0 → 100 once.

  • Book-level progress. Prefer aggregate byte progress across all audio files; fall back to file-weighted progress when sizes are unavailable. Show the current file's name and size while downloading.
  • A real finalizing stage. Cover download and local-store finalization are a finalizing stage — don't show 100% before the completion toast. The cover is part of the offline payload but isn't surfaced as a user-facing file.
  • Route memory. sourceBookRoute records whether the download started from home or search, so re-entry returns to the right place.
⬇️
The download request

Files come from downloads-api.ts via the active session's serverUrl, using /api/items/{itemId}/file/{ino}/download?token=…. Two headers matter: keep Authorization for clients that honor it, and send Accept-Encoding: identity so a reverse proxy doesn't gzip large media.

The download sheet is the detailed status surface, but it can be dismissed while the download continues. The active toast's Open action pushes the source book route (with a one-time sheet-open token via getBookDetailHref()) so the book screen still has a working back button.

How the app knows it's offline

authStore.isOnline is the canonical flag, updated by a NetInfo subscription in useAuthBootstrap. Two pieces lean on it: the request gate and the UI.

A book is playable offline only when downloaded audio tracks exist (selectHasPlayableBookDownload). Offline UI prefers cached data and avoids aggressive background retries — the banner offers a user-driven retry instead of polling.

Two states that look similar but aren't

🔀
Downloaded-only mode ≠ an offline session

Downloaded-only mode is entered after explicit logout when downloads remain: Home shows only downloaded books, server browsing is hidden, and cached library data must not be exposed as browsable until sign-in. An offline User Session is different — you're still signed in, connectivity is just temporarily gone, and the remembered Active Library stays visible with offline indicators. Keeping these distinct is why a dropped connection never looks like a logout. (See Auth & Sessions.)

Offline write durability

Anything that can't reach the server while offline is queued and flushed on reconnect, in order: progress → bookmark creates → bookmark deletes. The progress queue keeps only the latest entry per book, user-scoped. Full rules live on Progress & Sync.
