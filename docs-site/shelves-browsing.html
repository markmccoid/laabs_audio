Home & Shelves

The Home screen is a stack of shelves assembled entirely from local state, so it renders instantly and works offline. Three different kinds of shelf — derived, custom, and playlist-backed — are merged by one hook.

🗝️
Everything is scoped

All bookshelf state is keyed by activeLibraryUserKey + activeLibraryId (via toHomeShelfScopeKey). This is what stops one user's or library's shelves from leaking into another's on a shared device.

How a Home render is assembled

useHomeShelves() is the orchestrator. It reads scoped settings and custom shelves, pulls one SQLite home projection, derives the computed shelves, merges in custom and playlist shelves, applies ordering, and exposes both full and Home-trimmed arrays.

Playlist shelves have sync state

Playlist shelves are optimistic local projections of server playlists — the device store holds them so the app can render and mutate immediately, but the server is the source of truth for whether the playlist still exists. Each carries a syncState:

syncStateMeaning
syncedBacked by a playlist currently known on the server.
pendingOptimistic create/update awaiting server confirmation.
unsyncedA local operation still needs to sync.
missingThe server no longer returns the backing playlist.
🚫
Missing shelves are filtered, not repaired

A missing playlist shelf must not appear in Home, in book Shelf Membership menus, or in Settings. useHomeShelves and useShelfMembershipOptions filter them out rather than showing a repair state. (Future cleanup removes the records once server absence is confirmed.)
