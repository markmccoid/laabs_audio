Decisions (ADRs)

The architecture decisions behind the systems in this handbook, condensed. ADRs are point-in-time records — don't re-litigate them; if one blocks you, propose superseding it.

🧭
How to read these

Each links to its full record in docs/adr/. Several early decisions are superseded by later ones as the session/identity model matured — read the superseding ADR for current behavior and the original for the "why" that led there.

Playback & progress

ADRDecisionStatus
0005A durable Progress Sync Intent is written before attempting remote sync, for every meaningful moment (pause, seek, stop, switch, finish, background, interruption).Active
0007Streamed playback start attempts stay provisional until the first track actually becomes playable, so bad connectivity can't leave a misleading "ready" state.Active
0012Play/pause/start are modeled as one Playback Control Intent that settles on the audible state — no transient starting/pausing states.Active
0013Resume Resolution is observable and seeds the Displayed Listening Position while a book opens.Active
0018Repeated skip commands accumulate into one Skip Burst — instant display update, one bounded position change applied.Active
