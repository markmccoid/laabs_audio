## Findings considered and rejected

So nobody re-audits these:

- **"MMKV credential leak" (SEC-01, subagent-reported)** — REJECTED. Verified
  `auth-store` `partialize` (`auth-store.ts:584`) persists only
  `activeLibraryId/Name/UserKey` + `storedUserId` to MMKV; tokens, passwords,
  username, and server URL go to `expo-secure-store` (`auth-storage.ts`). MMKV
  holds library IDs + a user UUID — not credentials. Not worth a plan.
- **"Home-shelf Zustand selectors return a new identity every render" (PERF-01)**
  — REJECTED as stated. Verified `use-home-shelves.ts:204-234`: selectors return
  stable store references or shared `EMPTY_*` constants. Any real re-render cost
  comes from broad `device-books-store` setState fan-out during download ticks —
  which needs **profiling** (argent React profiler on a large-library Home
  scroll) before any refactor, not a blind plan.
- **Toast "blank/incorrect progress" claim (CORRECTNESS-01)** — DOWNGRADED. The
  duplicated `description` at `active-download-toast-coordinator.tsx:216` is the
  *same* variable as `options.description`; it's dead duplication / a `tsc`
  error, not a behavior bug. Folded into plan 003 (item #2).
- **`previousTrack` unguarded `queue[currentTrackIndex]` (CORRECTNESS-03/05)** —
  NOT PLANNED (low confidence). `player-service.ts:2518`; `currentTrackIndex` is
  service-maintained and generally valid; the crash needs a speculative race. Add
  optional chaining opportunistically if touching that code, but not worth a
  dedicated plan.
- **`http://` server URLs accepted (SEC-02)** — DEFERRED to maintainer judgment
  (listed under "Direction" in the audit, not a ranked bug). Likely a deliberate
  LAN/self-hosted tradeoff. A cheap one-time "insecure connection" confirmation
  would close the gap without blocking LAN users — implement only if the
  maintainer wants it.
- **`npm audit` advisories (DEP-01: 1 critical/3 high)** — NOTED, not planned.
  All are build-time/transitive (`shell-quote` via build tooling,
  `@xmldom/xmldom` via `@expo/config-plugins`, `minimatch`/`picomatch` in glob
  chains) — low runtime leverage. Re-run `npm audit` after the next Expo SDK
  bump; revisit if anything reaches app runtime.
- **66 `console.*` calls / no logging abstraction (DX-02)** — NOTED, low
  leverage. A `logger` wrapper is reasonable future hygiene but not worth a plan
  now.
