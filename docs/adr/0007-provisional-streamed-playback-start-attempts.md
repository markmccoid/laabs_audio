# Provisional Streamed Playback Start Attempts

The Cancel loading presentation and Pause-cancels-preparation behavior are superseded by [ADR-0042](0042-latest-requested-playback-state.md), implemented on 2026-09-30. The bounded failure, retry, and committed-progress protections below remain required.

Bad connectivity can let Audiobookshelf create a Streamed Playback Session while the first streamed track never becomes playable, leaving LAABS Audio in a misleading loading or ready state. Streamed autoplay treats the session as provisional until the target track reaches confirmed audible playback; only then does the attempt become Active Playback. Start, resume, and paused restoration use a 20-second attempt budget including session information, native preparation, and audio confirmation. If streamed transport fails, LAABS Audio resets to no loaded Active Playback, exposes an actionable error and retry control, preserves the last confirmed Listening Position, and closes the provisional Streamed Playback Session best-effort without syncing unconfirmed progress. Retrying obtains a fresh streamed source.

Successful audible playback releases its Playback Control Intent before follow-up checkpoints finish. Native checkpoint failures remain separately bounded storage errors: they pause playback and preserve previous committed evidence rather than being retried as connectivity failures. Silent Startup Active Playback Restore failure leaves an unloaded, idle player while retaining its saved playable identity and Listening Position. Phone controls can request silence during preparation or replace its target, and foreground reconciliation enforces expired attempt deadlines after JavaScript suspension. See [the fortification plan](../streaming-playback-fortification-plan.md) for the regression and device verification cases.
