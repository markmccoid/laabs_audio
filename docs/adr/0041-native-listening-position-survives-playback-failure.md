# Native Listening Position Survives Playback Failure

Normal audiobook and Episode playback commits its Listening Position in an owner-scoped native SQLite ledger. Native capture runs once per second independently of JavaScript delivery, with immediate checkpoints at interruption, pause, relocation, source replacement, natural completion, and teardown. WAL with FULL synchronization makes a successful commit receipt the durability boundary. A crash between samples can lose the unsampled interval; a successful checkpoint must survive process termination.

Loading or requesting playback is not evidence of either an applied seek or audible playback. The audio engine returns the confirmed native position and waits for native transport movement before settling a Playback Start Attempt. A failed seek preserves the preceding confirmed Listening Position. Intentional backward changes create a new revision through a command journal; stale samples and callbacks cannot undo them. Auto Rewind uses a command identity derived from its Listening Interruption and does not run again during automatic stream recovery.

The ledger is permanent recovery evidence. Reading, projecting, or acknowledging it never consumes it. Projection and server acknowledgements advance sequence watermarks without changing the saved position. MMKV, browsing caches, and Displayed Listening Position remain derived projections. Unsynced native evidence takes precedence during Resume Resolution; existing server-forward resolution remains available after native evidence has been synchronized. This does not create a global order across Audiobookshelf devices.

Each playback assignment freezes its Audiobookshelf User Identity and playable identity. Generation, revision, sequence, and load identity fence late work. Progress requests serialize per owner/playable and abort on owner or endpoint changes; delayed responses cannot project old positions or replace a newer Progress Sync Intent. Native evidence remains per owner after logout. Temporary previews and ambient playback do not change normal Listening Position.

This **supersedes ADR-0021's decision to omit an owner tag** from the saved startup pointer. `playbackStore` now persists its owner and startup restore checks it. Session teardown remains required, while native evidence intentionally outlives that teardown. Legacy unscoped UserDefaults evidence is retained for diagnosis rather than attributed to an unproven owner.

Stalled streamed playback gets at most two source reconstruction attempts and a 30-second recovery budget. Each attempt starts from committed evidence and obtains a fresh stream source. Explicit pause, relocation, source change, logout, or a newer load cancels older work. Native monotonic heartbeat evidence checks the recovery deadline after JavaScript suspension. Storage failures pause playback and surface an error instead of being retried as network failures. Missing native protection requires rebuilding the native app; it does not silently fall back on iOS/Android. Web continues using its existing persistence.

Real SQLite process-kill tests are part of regression verification. AirPods announcements, locked-phone file protection, extended background listening, power cost, and supported-device timing remain physical-device acceptance checks.
